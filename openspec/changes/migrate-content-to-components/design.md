# Design

## Context

Measured on `main` in `reposilite-frontend/` (paths checked against the tree when this change was written; line numbers are the
maintainer's inventory and are re-read at the start of each wave):

- 60 Vue files carry `rounded-corner-medium` or `rounded-corner-large` by hand. `src/components/md/MdCard.vue` already draws
  `rounded-corner-medium p-4` and is used by 8 files. The corner radius tokens are in `src/styles/md3/shape-elevation-motion.css`
  (`--md-sys-shape-corner-medium` 12px, `-large` 16px).
- 24 files set `font-mono`. `src/style.css` sets `--font-mono` in its `@theme` block.
- Seven files carry a `<style>` block: `src/components/card/SnippetsCard.vue` (the app-wide `::-webkit-scrollbar` rule), 
  `src/components/browser/FileUpload.vue` (a rule for the `vue-upload-component` class), `src/components/settings/SettingsView.vue`
  (read-only inputs and the save bar clearance, scoped to `.settings-view`), `src/components/md/MdSnackbar.vue`,
  `src/components/md/MdLinearProgress.vue`, `src/components/renderers/OptionalRenderer.vue` and
  `src/components/renderers/ObjectRenderer.vue`. Wave 3 and wave 4 remove the four in views; the two in `md/` and the two renderers
  are checked and removed only if their rules are structural.
- The window classes are not defined yet. `src/styles/md3/window-margins.test.js` already uses the MD3 medium threshold of 600px for
  the gutter, and `src/style.css` defines the `.container` gutter inside `@layer components`, so the gutter does not depend on
  Tailwind's breakpoints.
- Non-MD3 breakpoints in use: `sm:` in 15 files, `md:` in 5, `lg:` in 3, `xl:` in 2, and literal widths in the maintainer's
  inventory (480, 720, 900, 960, 1024, 1240, 1920, 2560 pixels and `max-[599px]`).
- Test hooks: 71 files use `data-test`, and 177 files carry a `data-ingot-component`. Tests select by these, so the change does not
  need new hooks for the existing tests.
- Primitives present in `src/components/md/`: `MdButton`, `MdCard`, `MdCheckbox`, `MdChip`, `MdChipInput`, `MdIconButton`,
  `MdLinearProgress` (the progress primitive, not `MdProgress`), `MdNavigationBar`, `MdNavigationRail`, `MdOverflowMenu`, `MdRadio`,
  `MdSelect`, `MdSideSheet`, `MdSnackbar`, `MdSwitch`, `MdTextArea` and `MdTextField`. `MdTextField` takes `variant`
  (`filled` or `outlined`, default `filled`). The primitives named in `proposal.md` as coming from `add-md3-component-catalogue`
  are not in the tree yet; this change waits for them.
- Renderers are in `src/components/renderers/`: `MdTextFieldRenderer.vue`, `MdTextAreaRenderer.vue`, `MdSelectRenderer.vue`,
  `MdColourFieldRenderer.vue`, `OneOfRenderer.vue`, `TagsFieldRenderer.vue`, `ArrayListRenderer.vue`, `ConstantRenderer.vue`,
  `UnsupportedRenderer.vue`, `SectionRenderer.vue` and `BooleanSwitchRenderer.vue`.
- The page `IndexPage` is `src/pages/IndexPage.vue`, not under `components/`.
- The anchors contract: `src/anchors/registry.json` (contract 1) with `stable` and `experimental` names. `settings-hub` is `stable`
  with no parts; `settings-view` is `stable` with `ownElement: false`. `docs/gitbook/reference/dashboard-anchors.md` is generated by
  `npm run anchors:doc` from the registry.
- `src/anchors/anchors.test.js` checks the registry.

## Goals

- Every card, section, row, table, code sample and field of the dashboard is one shared component, so a visual rule changes in one
  place.
- Styling is Tailwind utilities that resolve to MD3 tokens and window classes. No custom class, no `<style>` block, no raw colour,
  no magic number that bypasses a token.
- One card radius, one card padding, one heading size per level, one row geometry, one field variant, one breakpoint set.
- Anchors stay as they are for plugins and operators.

## Non-goals

- New features, new routes, new data, new requests.
- Colour token values and the surface steps (`fix-surface-hierarchy-and-page-header`).
- Dialog and menu shells and status messages (`unify-dialogs-menus-and-feedback`).
- The gate's rules and the primitive catalogue (`add-ui-style-gate`, `add-md3-component-catalogue`).

## Decisions

### D1. One card

`MdCard` is the only card container. Its radius is `rounded-corner-medium` (12px). Its padding is `p-4` (16px) at every window
size, and its variants stay `elevated`, `filled` and `outlined`. A card that holds a table or a full-bleed list uses
`padding="none"`, which removes the padding and clips the content to the radius, so no card is built with `p-0` or a negative margin.

The value `none` of the catalogue's `padding` prop on `MdCard` is added in wave 1. The default is unchanged. A card with an inset header uses `MdSection` inside the card,
not a second card.

Open maintainer question 2 records the alternative of 16px. Changing it later is one class in `MdCard`.

### D2. One section, one heading per level

`MdSection` (from `add-md3-component-catalogue`) renders a `section` with a heading. Its prop `level` takes `2` or `3`; the default
is `2`. This change sets the heading text it leaves open: `md-title-medium` at level 2 and `md-title-small` at level 3. Level 1 is the page heading owned by
`fix-surface-hierarchy-and-page-header`. A component that nests inside a section uses level 3 and never level 4.

`SectionRenderer` computes its level from its depth and clamps it to 3. `RepositoryAccessCard` (level 4 without parents today)
gets a level-2 section or a level-3 subsection, depending on where it sits. The inset of a section heading matches the inset of its
content, which fixes the labels that sit left of their content today.

### D3. Lists and rows

One row geometry, owned by `MdListItem`: a minimum height of 56 pixels for a two-line row, 48 pixels for a one-line row, a horizontal
inset of 16 pixels, and a state layer from `md-state-layer`. `MdList` draws the divider between rows with `divide-y` and
`divide-outline-variant`. A list never uses an arbitrary child selector such as `[&>li+li]:after`, and no row adds its own divider.

Selection: the catalogue's selectable `MdListItem` takes `selected`, and this change makes it set `aria-current="true"`. A list computes its selected key once, in one computed property,
and passes a boolean per row. The four copies of the test in `PrincipalsPanel` collapse into that one property.

Link rows use `MdNavigationItem` (a router link with the row geometry), so the link, the hover state and the current state are the same
everywhere. Redundant resets (`m-0`, `p-0`, `list-none` on an `ul` that `MdList` already resets) are removed.

`overflow-wrap: anywhere` (`[overflow-wrap:anywhere]`) is replaced by `break-words` on the text element, and only where a value can be
longer than its column. Long identifiers (repository names, token ids) use `break-all` on the identifier element, not on the row.

`MdKeyValueList` renders a definition list of label and value pairs, with one label width and one value width per breakpoint, and is
the only key and value layout. `MdBadge` is the only status label, with its tone as a prop (`StatusLabel` takes a status enum, see
wave 5).

### D4. Tables

`MdDataTable` comes from `add-md3-component-catalogue` and takes `columns` (key, label, `sortable`, `priority`) and `rows`. This
change adds the sort helper and the window-class priorities to it. A sortable header is a real `button` inside `th`,
with `aria-sort` on the `th`. The sort is a pure function `sortRows(rows, column, direction)` in `MdDataTable.sort.js`, tested with
plain input and output. A column with a `priority` (`base`, `expanded`, `large`, `xlarge`) is hidden below its window class with
`hidden` and the window class (for example `hidden expanded:table-cell`), not with a per-width literal.

`MdDataTable` sets no minimum width. Its container scrolls horizontally (`overflow-x-auto`) when the columns need more room. The
repositories table keeps its four sortable headers and its actions cell, both at the same padding (`py-3`), the padding that the
other cells already use. Column order and visible columns at each window class are listed in the table's test.

### D5. Code

`MdCode` is inline code as `add-md3-component-catalogue` defines it (the `md-code-medium` utility of
`refactor-md3-token-utilities`, a surface role, `rounded-corner-extra-small`); this change uses it and does not restyle it.
`MdCodeBlock` is the block (a `pre` inside `MdCard`-like padding of `p-4`, `overflow-x-auto`, the `md-scrollbar` utility that wave 3
adds to `src/style.css` for a thin scrollbar). `MdCopyableCode` is `MdCodeBlock` with a copy button (an `MdIconButton` with an
`aria-label`).

The `<style>` block in `SnippetsCard.vue` goes away with the app-wide `::-webkit-scrollbar` rule. Scrollbars of the rest of the
dashboard return to the browser default, unless a component opts into `md-scrollbar`. That is a visible change and is listed in
wave 3's pull request with before and after screenshots of a page with a scrollbar.

The four identical `pre` elements in `RepositorySnippet.vue` become one `MdCodeBlock` with four `MdCopyableCode` rows. The anchor
`repository-snippet` stays on the root of the snippet and `artifact-snippet` stays on the artifact snippet root. The nested `px-2`
insets in `SnippetsCard.vue` (lines 174, 181 and 211 in the inventory) go, so the title sits at the card's own inset.

Font sizes in code: `text-xs leading-5` in `FailuresSheet.vue` becomes `md-label-medium`, and `text-sm` and `text-xs` in
`SecretOnceDialog.vue` become the type scale classes. The chart in `TimeSeriesChart.vue` takes its font sizes from the typescale
through `src/components/md/typescale.js` (a plain object with the same numbers as `typography.css`), and a test reads `typography.css`
to check that the numbers agree.

### D6. Forms and controls

Form controls are the primitives: `MdRadio`, `MdCheckbox`, `MdSelect`, `MdSwitch`, `MdLinearProgress`, `MdButton` and `MdIconButton`.
A link that looks like a button is an `MdButton` with `href` (the `href` prop exists today), not a `RouterLink` with classes.

Field variant (open question 3): `MdTextField` defaults to `outlined` after wave 4, and every form uses the default. A filled field is
an explicit prop and the only use is in `ProfileCard` if the default is kept; the change lists each such use.

Form scaffolding, new components (proposed names, placed in the folder that owns their use):

- `MdFieldGrid` (`src/components/md/`): one column below the `expanded` window class, two from it. It replaces the `sm:grid-cols-2`
  grids of `LdapPanel` and the others.
- `MdFieldset` (`src/components/md/`): a `fieldset` with a `legend`. It replaces a `span` that is styled as a legend in
  `CreateTokenDialog.vue` and the groups of `PolicyDialog.vue` and `SearchFilters.vue`.
- `MdSaveBar` (`src/components/md/`): the sticky bottom bar with its clearance from `--app-bottom-bar-height` and the safe area inset.
  It replaces the bars of `AuthenticationGroupForm.vue`, `LdapPanel.vue`, `UnsavedChangesBar.vue` and the `calc` offset of
  `SettingsView.vue`, and its clearance is a utility, not a `<style>` rule.
- Wizard parts in `src/components/settings/wizard/`: `WizardStepIndicator.vue`, `WizardChoiceCard.vue` (the choice card that is copied
  four times in `RepositoryWizard.vue`), `WizardFieldGroup.vue`, `WizardRemoteFields.vue`, `WizardReviewSummary.vue` and
  `WizardProgressList.vue`. `RepositoryWizard.vue` keeps its data flow and its anchor.

Renderer prop wiring: the six renderers (`MdTextFieldRenderer.vue`, `MdTextAreaRenderer.vue`, `MdSelectRenderer.vue`,
`MdColourFieldRenderer.vue`, `OneOfRenderer.vue` and `TagsFieldRenderer.vue`) repeat the same mapping from JSON Forms props to primitive
props. The mapping moves to one composable, `src/components/renderers/useFieldBinding.js`, which returns the props and the `onInput`
handler. Its test checks the mapping with plain objects.

`FileUpload.vue`'s `<style>` rule for the `vue-upload-component` class is removed only after the class is confirmed in the rendered
drop zone (wave 4 checks it in a Playwright snapshot before and after).

### D7. Breakpoints

The MD3 window classes become the only breakpoints. In `src/style.css`, inside the `@theme` block:

```
--breakpoint-*: initial;
--breakpoint-medium: 600px;
--breakpoint-expanded: 840px;
--breakpoint-large: 1200px;
--breakpoint-xlarge: 1600px;
```

The variants are `medium:`, `expanded:`, `large:` and `xlarge:`, and the max variants (`max-medium:`) follow from the same names.
The default, compact, has no prefix. The `.container` gutter keeps its own media query (600px) and is not changed.

Mapping of the old values, rounding to the nearest MD3 threshold and to the lower one on a tie:

| Old | New | Where (inventory) |
| --- | --- | --- |
| `sm:` (640px) | `medium:` | LdapPanel, NodeAddField, IndexPanel, SegmentedControl, SearchResultRow and others |
| `md:` (768px) | `expanded:` | InstanceStatusPanel, ConsoleView, HeaderHero and others |
| `lg:` (1024px) | `large:` | InstanceStatusPanel, ConsoleView, SettingsView |
| `xl:` (1280px) | `large:` | RepositoryOverview and others |
| `max-[599px]` | `max-medium:` (already replaced by `refactor-md3-token-utilities`) | SettingsView save bar |
| 480px | `medium:` | TokenList |
| 720px | `medium:` (tie, lower) | TokenList, AuditEventRow, AuditView |
| 900px | `expanded:` | MenuPanel |
| 960px | `expanded:` | AccountView |
| 1024px | `large:` | ResourceTrends, RepositoryOverview |
| 1240px | `large:` (already named by `refactor-md3-token-utilities`; the value moves to 1200px, question 4) | SideNavLayout |
| 1920px and 2560px | `xlarge:` | RepositoriesTable, RepositoryOverview, FileBrowserView |

Each row is checked in the wave's review by a before and after screenshot at the two widths on each side of the threshold where the
layout changes. A test in `src/styles/md3/breakpoints.test.js` reads `style.css` and asserts that the four names above are the only
`--breakpoint-*` values and that `--breakpoint-*: initial` is present.

Visible effect: a layout that changed at 1024px changes at 1200px; one that changed at 1920px changes at 1600px. The before and after
screenshots at 1440px show the difference for the `large` threshold, and the screenshots at 1920px show `xlarge`.

### D8. Anchors

The rule from `proposal.md` holds for every wave. Merging two components keeps both names: the wrapper keeps the outer name and the
inner element keeps the inner name. A new name is added to `src/anchors/registry.json` with `stability: "experimental"` unless it
replaces a stable name. `docs/gitbook/reference/dashboard-anchors.md` is regenerated in the same wave by `npm run anchors:doc`.
`anchors.test.js` runs in the same commit as the registry change.

### D9. Waves and order

1. Cards and sections. `MdCard`, `MdSection`, heading levels, the `padding="none"` card.
2. Lists and rows. `MdList` family, selection, link rows, redundant resets.
3. Tables and code. `MdDataTable`, code primitives, the removal of the snippets `<style>` block and the app-wide scrollbar rule.
4. Forms and controls. Native controls, buttons, field variant, scaffolding, wizard parts, renderer helper, `FileUpload` and
   `SettingsView` style blocks.
5. Breakpoints and leftovers. The theme change, the literal widths, the arbitrary values, the `!important` overrides, the opacity
   fades, the font weights, `StatusLabel`, `StatTile`, `TimeSeriesChart`, the duplicated footer and the icon lookup in `IndexPage`,
   then the gate baseline.

Each wave is one pull request (open question 1), merged before the next starts, so that every wave is reviewed against the same main
branch. Wave 5 contains the breakpoint theme change, which is the one change that moves every view at once, so it goes last.

### D10. Tests

Every test follows F.I.R.S.T. Unit tests use `@vue/test-utils` with a fresh mount per test, no timers, no clock read, no network.
Tests select by `data-test` or by the anchor name, never by a utility class. New tests per changed behaviour:

- `MdDataTable.sort.test.js`: the pure `sortRows` function, with plain arrays, both directions and a stable order for equal keys.
- `MdDataTable.test.js`: `aria-sort` on the sorted header only, the button inside the header, and the hidden class per priority.
- `MdListItem.test.js` and `MdList.test.js`: `aria-current` on the selected row only, one selected key for the list.
- `MdDisclosure.test.js`: `aria-expanded` toggles, the content is hidden while collapsed, and the control keeps focus.
- `MdCard.test.js` (extended): `padding="none"` removes the padding.
- `useFieldBinding.test.js`: the mapping from JSON Forms props to primitive props, with plain input.
- `breakpoints.test.js`: the theme names and the `initial` reset, read from `style.css` source.
- `typescale.test.js`: the chart's font sizes agree with `typography.css`.

Existing tests that select by a utility class are changed to select by `data-test` or by an anchor, in the wave that changes the class.
Each changed expectation is listed in the pull request.

### D11. Screenshots

Two sets per wave PR, both in light and dark, stored with the pull request and not in the repository:

- Before and after at 320, 600 and 1440 pixels, the widths that the change rules set for any visible change.
- The wave's own screenshots at 390, 840, 1280 and 1920 pixels.

Vitest and Playwright runs go through the slot runner (`heavy npx vitest run <pattern>`, `heavy npx playwright test <suite>`), with one
suite at a time while a wave is in review.
