# Back up and restore the settings

The shared settings are the configuration that the dashboard edits: the repositories, the search, the login providers and the other settings domains. They live in the database. This page covers only that part. For the database, the files and the S3 bucket as a whole, see [Back up and restore](back-up-and-restore.md).

A settings file is a copy of the saved settings that you keep outside the instance. Take one before an upgrade or before a change you may want to undo, and use it to move a configuration to another instance.

## What the file contains

* The saved settings. Unsaved changes in the dashboard are left out.
* The secret values, such as S3 keys and tokens. They are inside the encryption, in clear. Ingot reads the stored secrets before it writes the file, so the file restores into an instance with another settings key or with none. See [Settings encryption](../../references/settings/settings-encryption.md).
* Nothing else. Users, teams, tokens, repository files and the database contents are not in the file.

The file is protected by a passphrase that you choose when you export it. Ingot does not keep the passphrase. Without it the file cannot be opened, and nobody can recover it.

{% hint style="warning" %}
The file holds your secrets inside the encryption. Store it with the same care as the database. The passphrase protects this file only. A token with the settings area can already read the stored secrets through the settings API, unless `hideSettingsSecrets` is on, so keep those tokens as tightly held as the passphrase.
{% endhint %}

## Export the settings

The export needs the settings area (`ingot.admin.settings`).

1. Open Administration, then Maintenance, and choose the **Settings backup** tab. The tab appears only to a visitor who may edit the settings.
2. Choose **Download as JSON**. The name says JSON, but the file is the encrypted envelope and not readable text.
3. Enter a passphrase of at least 12 characters and enter it again. The dialog shows a strength line. A passphrase of several unrelated words, or one generated by a password manager, is easier to remember and harder to guess than a short mixed one. Use the show and hide control to check what you typed.
4. The browser downloads the file. The export is recorded in the audit log, without the passphrase.

## Store the file and the passphrase apart

Keep the file and its passphrase in different places. A file stored next to its passphrase is not protected. A common setup is the passphrase in a password manager and the file in your backup storage. Check the pair once by restoring the file into a test instance.

## Restore the settings

Restoring fills the draft, and nothing reaches the instance until you save. The steps are the same for a fresh instance and a running one.

1. Open Administration, then Maintenance, then the **Settings backup** tab, and choose **Import settings**.
2. Choose the file. Enter its passphrase. A wrong passphrase, a changed file and an unknown version all show the same error, so the message does not say which one it is.
3. Ingot checks the file against the settings schemas and puts its values in the draft. The values that the file names replace the current ones. The other settings and domains stay as they are.
4. Review the list of changes in the review sheet. Revert puts one change back to its saved value. When the list is right, save.

A plain JSON settings file from before the encryption has no passphrase. It is applied directly, as it always was.

A settings file restores settings only. For a full recovery, restore the database and the files first, as described in [Back up and restore](back-up-and-restore.md), and then restore the settings file if the settings in the database are not the ones you want.

## Reset the settings to their defaults

The factory reset sets every setting back to its default value and saves it on all instances at once. It does not remove users, tokens, teams or repository files.

The reset has no undo. The only way back is to import a settings file that you exported before the reset. Export the settings first.

The reset is in the **Danger zone** at the end of the Overview tab of **System and support**. The dialog asks for confirmation. The Settings backup tab links to it.
